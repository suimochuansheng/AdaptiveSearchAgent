# 前端 ↔ 后端 对接验证指南

> **目的**：通过手动操作逐步验证 Chainlit 前端与 FastAPI 后端的对接是否完成。
> **前提**：后端服务已启动，LLM 和搜索服务可用。
>
> 所有文件路径以 `/home/ubhuazhu/dev_pros/AdaptiveSearchAgent` 为根目录。

---

## 启动准备

```bash
# 终端 1：启动后端 (FastAPI)
cd /home/ubhuazhu/dev_pros/AdaptiveSearchAgent
eval $(poetry env activate)
poetry run uvicorn api_main:app --reload --port 8000

# 终端 2：启动前端 (Chainlit)
cd /home/ubhuazhu/dev_pros/AdaptiveSearchAgent/frontend
eval $(poetry env activate)
chainlit run app.py --port 8001
```

打开浏览器访问 `http://localhost:8001`

## 测试场景总览

| 编号 | 场景 | 覆盖路径 | 验证点 |
|------|------|----------|--------|
| 1 | 后端无法连接 | 错误处理 | 前端显示错误提示 |
| 2 | 正常首次搜索 | 路径A（idle → message → execute → completed） | SSE 流式输出、最终报告、KPI 统计 |
| 3 | 重启后中断恢复（批准） | 路径B（interrupted → resume yes） | 恢复执行、继续输出 |

| 6 | HTTP 错误处理 | 错误路径 | 5xx / 超时 → 前端错误提示 |
| 7 | 中断审批循环 | interrupt → 弹窗 → 批准/拒绝 | AskActionMessage 弹窗交互 |
| 8 | 用户主动停止 | on_stop | 日志记录 |

## 场景 3：中断恢复 — 批准执行

**前置条件**：已有一个被中断的会话（在审批环节，不完成审批直接关掉浏览器标签页）。

**步骤**：
1. 重新打开 `http://localhost:8001`
2. 应弹出选择框：
   ```
   🔔 检测到有未完成的会话（等待审批中），是否继续？
   [✅ 恢复上一次对话] [🆕 开始新对话]
   ```
3. 点击 **✅ 恢复上一次对话**
4. 看到 `⏳ 正在恢复之前的对话，请稍候...`
5. 等待流式输出继续

**预期结果**：
- 后端从 checkpoint 恢复执行（`Command(resume=...)`）
- 前端继续流式显示后续事件

**对应代码**：
- 前端弹窗：`frontend/app.js:168-184`
- 恢复请求：`frontend/app.js:190-206` → `api_main.py:201-221`
- Checkpoint 恢复：`api_main.py:203` → `src/graph_factory.py:122` → `src/checkpointer.py`

**验证通过标准**：
- [ ] 弹窗正确显示两个选项
- [ ] 选择"恢复"后显示等待提示
- [ ] 后端从断点继续执行（不重新开始）

## 场景 5：并发保护 429

**步骤**：
1. 在浏览器中先发一个问题（不要太快完成）
2. 用 curl 立即对同一 thread_id 发第二个请求：
   ```bash
   # 获取 session ID（从浏览器 URL 或 DevTools Network 中获取 thread_id）
   curl -X POST http://localhost:8000/chat/stream \
     -H "Content-Type: application/json" \
     -d '{"thread_id":"你的thread_id","message":"并发测试"}'
   ```

**预期结果**：
```json
{"detail":"会话正在执行或被中断，请等待或提供 resume_value 恢复"}
```
HTTP 状态码：**429**

**对应代码**：`api_main.py:313-316`

**验证通过标准**：
- [ ] 对正在执行的会话再次请求返回 429
- [ ] 返回的 JSON 包含 `detail` 字段

## 场景 7：中断审批循环

**前置条件**：后端配置了人工审批节点（`human_approval_node`），且回答置信度达标触发了审批。

**步骤**：
1. 发送一个问题，正常执行
2. 当置信度达标（≥80%）后，前端应弹出审批框：
   ```
   ⏳ 等待审批：是否批准当前回答？
   [✅ 批准] [❌ 拒绝]
   ```
3. 点击 **✅ 批准** → 看到 `✅ 已选择：批准，继续执行...`
4. 等待 writer 生成最终报告

**或者**：
3. 点击 **❌ 拒绝** → 看到 `✅ 已选择：拒绝，继续执行...`
4. 图执行结束（END 节点）

**预期结果**：
- interrupt 事件被前端正确捕获
- AskActionMessage 弹窗显示审批按钮
- 用户选择后，前端再次调用 `_stream_agent_with_interrupt(resume_value=...)`

**对应代码**：
- 中断抛出：`src/agents/human_approval.py:12` (`interrupt()`)
- 中断捕获：`api_main.py:289` → `api_main.py:325-333`
- 前端弹窗：`frontend/app.py:257-276`
- 恢复请求：`frontend/app.py:318-327`

**验证通过标准**：
- [ ] 中断事件正确触发弹窗
- [ ] "批准" 后继续执行 → 生成最终报告
- [ ] "拒绝" 后执行结束 → 无最终报告

## 快速验证脚本

以下 curl 命令可快速验证后端 API 的各个端点（无需前端）：

```bash
BACKEND="http://localhost:8000"

# 1. 健康检查
echo "=== 1. 健康检查 ==="
curl -s $BACKEND/health | python3 -m json.tool

# 2. 状态查询
echo -e "\n=== 2. 状态查询 ==="
curl -s $BACKEND/status/test-manual-check | python3 -m json.tool

# 3. 正常 SSE 流式请求（5 秒后手动 Ctrl+C 停止）
echo -e "\n=== 3. SSE 流式请求（按 Ctrl+C 停止） ==="
curl -N -X POST $BACKEND/chat/stream \
  -H "Content-Type: application/json" \
  -d '{"thread_id":"manual-test-001","message":"1+1等于几？简短回答"}'

# 4. 请求体校验（缺少 thread_id）
echo -e "\n\n=== 4. 缺少 thread_id → 422 ==="
curl -s -X POST $BACKEND/chat/stream \
  -H "Content-Type: application/json" \
  -d '{"message":"测试"}' | python3 -m json.tool
```

## 2. 端口表（`agent/app/ports.py`）

| 端口 | 方法 | 幂等性要点 | 错误语义 | 并发安全 |
|---|---|---|---|---|
| `AgentRuntime` | `run_turn(session, hooks)` / `resume(session, command)` | 同 `thread_id` 续接；`resume` 的一次性凭据由审批存储兜底 | 流内错误走 `kind="error"`，不抛栈；`interrupt` 后不补 `final` | 同 `thread_id` 不得并发（调用方会话锁） |
| `ModelClient` | `stream_chat` / `complete` / `count_tokens` | 只读，重复调用不改状态；计数稳定 | 流式中途失败必须显式终止；计数不得抛"不支持" | 同实例可跨会话并发，缓冲按调用隔离 |
| `SessionStore` | `load` / `save` / `mark_ended` | `save` upsert；`mark_ended` 可重复 | 存储不可用抛领域异常，不用空对象冒充不存在 | 同会话串行/乐观锁；已结束不被 save 复活 |
| `ArtifactStore` | `put` / `get` / `search` | 同一指针 `get` 结果稳定 | `get` 未命中返回 `None`；写入失败不得返回假指针 | 并发 put 指针唯一；写入原子 |
| `TaskStore` | `enqueue` / `get` / `update` / `cancel` | `cancel` 幂等；终态不可逆 | `get` 未命中 `None`；`update` 不存在抛异常 | 状态迁移原子（CAS/事务） |
| `MemoryStore` | `append` / `recall` / `get_profile` / `upsert_profile` | `upsert_profile` 覆盖；`append` 不去重 | 存储不可用抛异常；新用户画像 `None` | 画像 last-write-wins；recall 最终一致 |
| `EventBus` | `publish` / `subscribe` | 至少一次，订阅方自行去重 | 单订阅方失败隔离，不阻断主循环 | 单订阅者按发布顺序 FIFO |

**合并决定（按要求）**：

- **不造 `TokenCounter`**：token 计数归并进 `ModelClient.count_tokens`，避免同一模型两套口径。
- **不造 `UserProfileStore`**：画像归并进 `MemoryStore.get_profile` / `upsert_profile`，避免跨端口双事务。

**`RuntimeEvent`**（`docs/contracts/runtime-event.md` §1/§2）：

```python
@dataclass(frozen=True)
class RuntimeEvent:
    kind: Literal["token", "tool_call", "tool_result", "interrupt", "final", "error"]
    payload: dict
```

纯数据、无方法；`ping` 不在六值内，也不进 `payload`。

`LangGraphRuntime` 的实现边界：

  `stream_conversation(graph, inputs, config, heartbeat_seconds=..., clock=...)`；

  审批存储 / 会话锁 / HTTP 状态码矩阵仍归入站适配器，不在运行时适配器里重复。
- `hooks`：只挂到 `configurable["runtime_hooks"]` 透传，本文件不做压缩/校验/预算。
- 依赖方向：`adapters -> app.ports -> domain`；`app` 不 import `adapters`；
  `agent.domain` 仍零 langchain/langgraph（`t12_checks.py` T12-014 通过）。

## 5. 0b：OI-T93-004（MCP spec 与可见 schema 漂移）

**根因**：`ToolSpec` 存的是 MCP 原始 `inputSchema`（带 `title`、无属性 description），
而模型看到的是 `convert_to_openai_tool(callable)` 的结果（LangChain 去 `title`、
把 docstring 的 `Args:` 变成属性 description、description 只留摘要）。两边不是同一份，
所以注册表按 B 校验、模型按 A 选参数。

**修法**（`agent/adapters/tools/mcp_client.py`）：

1. `ToolSpec.input_schema` / `description` 存在**模型真正看到的那一份**：先由远端
   `description` + `inputSchema` 建可调用体，再用 `convert_to_openai_tool(callable_)`
   的结果填 spec——只有同一份才可能不漂移。
2. 新增 fail-fast 自检 `_assert_visible_matches_payload()`：
   - description 必须是远端 description 的摘要（前缀；一边空一边不空也算漂移）；
   - visible `parameters` 必须无损覆盖远端 `inputSchema` 的每个约束（参数名集合、
     `type`、`required`、`enum`、嵌套 `properties`、`items`、`anyOf` 等）；
     不一致直接 `ValueError`，**不静默丢参数**。
3. `_schema_drift()` 忽略 `title`/`description`/`$schema` 这些展示字段（LangChain 本来
   就会重写它们），其余逐项比对。

**为什么不直接存原始 `inputSchema`**：LangChain 的 `convert_to_openai_tool` 对函数
硬编码 `rm_titles=True`，且 description 取 docstring 摘要；"原始 spec == 可见 schema"
在实现上不可能成立。若坚持存原始值，漂移只会继续存在。现在的口径是
**"spec = 模型可见；自检保证它没丢远端约束"**，符合 OI 要解决的"两边不是同一份"。

证据（真实 `scripts/mcp_server.py`，两工具逐项相等）：

```text
===== word_count
desc eq: True '统计文本的字符数、词数与行数。'
params eq: True
===== unit_convert
desc eq: True '单位换算：支持 km/m、kg/g、c/f 三组。'
params eq: True
```

T93 卡级脚本的 C6 探针（spec vs 模型可见）已由 open_issue 变绿；当前 C 类 open_issue
只剩 `C1b / C1c / C3`（均为既有性能/快照问题，非本卡引入）。

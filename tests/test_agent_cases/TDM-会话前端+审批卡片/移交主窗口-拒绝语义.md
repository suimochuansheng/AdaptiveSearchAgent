# 移交主窗口：审批「拒绝」应当终止本轮，而不是回灌后继续

> 来源窗口：前端 Bug 修复窗口（S3）｜日期：2026-11-24｜状态：**待主窗口裁决**（本窗口不改后端）
> 触发：用户实测「拒绝审批 → 立刻发新消息 → 用户消息消失、agent 却自己写了篇报告」

---

## 0. 一句话

现在 `reject` 的语义是「**这个工具不给你用，你换个法子继续答**」，于是模型绕过了审批：
实测拒绝 `deep_research` 之后，它自己写了 3095 字「深度调研报告」（带「1,200 QPS」「内部知识库」这种
没有检索支撑的数字）。建议改成语义「**拒绝 = 本轮到此为止**」。

## 2. 实测证据（真实链路：前端 :8202 + 后端 :8201，2026-11-24）

| 观测 | 数值 |
|---|---|
| 点「拒绝」→ resume 首个 token | **25.3s** |
| 拒绝后的续写长度 | **3095 字**（一整篇「深度调研报告」） |
| 拒绝 → 本轮结束 | **48.4s** |
| trace 标注 | `rejected_by_user`（**工具确实没执行、也没记账**，这点是对的） |
| 拒绝后 1s 发新消息（修复前） | 后端 `429`「该会话正在执行中」，且用户那句话被 Chainlit 输入框静默吞掉 |

**关键点**：工具确实没跑，但模型把「已拒绝」当成工具结果，自己把答案编出来了 —— 审批只拦住了工具，
没拦住产出。用户看到的是「agent 无缘无故开始回答」。

---

## 3. 为什么必须改（产品口径三条）

1. **绕过审批**：用户以为「我拦住了」，实际只拦住了工具调用；模型给出的内容看起来有数据、实际无来源，
   比直接报错更有害。
2. **成本语义被破坏**：拒绝的潜台词之一是「别花这笔钱」，但本轮仍继续消耗 25~48s 的 token。
3. **交互不可判定**：用户无法区分「这是它真答的」和「这是它被拒绝后自己编的」。

---

## 4. 业界参考（两派，判据是「批的是什么」）

**流派 A：拒绝 = 反馈给模型，本轮继续**
- [LangChain HITL 文档](https://docs.langchain.org.cn/oss/javascript/langchain/human-in-the-loop)：`reject` = 完全跳过执行该工具调用，并向智能体返回拒绝反馈。
- [OpenAI Agents SDK HITL](https://openai.github.io/openai-agents-js/guides/human-in-the-loop/)：interrupt 的 approve/reject 决议，reject 后 run 继续（还支持 sticky `alwaysReject`）。
- 典型：Claude Code / Codex 的权限拒绝——工具返回 denied 错误，模型换个安全做法。
- 适用：审批粒度是「这一下能不能做」，且模型有安全的替代路径。

**流派 B：拒绝 = 本轮/本次运行终止**
- [LangGraph HITL 概念](https://github.com/vksx/langgraph/blob/d0bf7837bd52f9f1b1887c33629a67b83fa2d44d/docs/docs/concepts/human_in_the_loop.md)：动作被拒绝时可以阻止图执行该步，**并可能采取替代动作**——走哪条边（含 END）由你决定。
- 生产系统对不可逆/付费动作（付款、部署、发邮件、调用有成本的第三方）一律 fail-closed。
- [aegra HITL 示例](https://github.com/aegra/aegra/blob/2693066413dfafce3fd21bf581f10bd2495b8dd3/docs/guides/human-in-the-loop.mdx)有专节「Ignore the tool call → **Skip the tool and end the turn**」。

**结论**：`deep_research` 是 `permission="dangerous"` + 有成本模型 + 单次可跑 600s 的**能力门**，
拒绝的语义是「这一轮我先不批这笔钱/这个长任务」→ 属**流派 B**。

---

## 5. 建议方案（最小可行）

**改语义**：`reject`（含 120s 超时自动拒绝）→ 消费 `approval_id`、不执行工具、不记账、
**本轮直接 END，不再进入模型推理**；SSE 只回一条可读 `final`，例如：

> 已拒绝执行 `deep_research`，本轮已结束。可以换一种方式继续提问。

任务状态照旧 `interrupted → idle/completed`，`approval_id` 一次性、409/410/429 语义一律不变。

**可选加分（用户明确提过）**：审批卡片加第三按钮「✏️ 拒绝并说明」，带一句 feedback 时才走
「回灌继续」——即流派 A 的受控版本。对应 `Decision` 需要新增枚举值（契约 v2 一并裁决）。

## 7. 验收口径（建议直接抄进卡面）

- 拒绝后 SSE 序列：`interrupt` → `POST …/resume` 200 → **1 条 final（已拒绝执行）** → 流结束；
  **不得出现任何 `token` 帧 / assistant 生成**
- 工具未执行、预算账本不变、trace 仍为 `rejected_by_user`
- 同一 thread 立刻发新消息：`POST /chat/conversation` **200**，无 409/429，且**只发 1 次**
- 120s 超时路径与手动拒绝同义
- 前端：拒绝后本轮立刻结束、输入框立即可用（已实现，见第 8 节）

## 8. 前端现状（**别重复修**）

已提交 `b62364b fix(frontend): 拒绝审批后新消息未渲染到对话流`：

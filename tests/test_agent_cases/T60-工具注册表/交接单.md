## 3. 设计要点

1. **顺序 = 基线**：`TOOL_SPECS` 按 `search_knowledge, search_tavily, calculator,
   deep_research, read_offload` 的插入顺序声明；`to_lc_tools()` 直接按该顺序取，
   不排序、不包装，返回对象与改造前**同一个函数对象**。
2. **不改 schema**：`spec.description` 与 `spec.input_schema` 直接取自
   `convert_to_openai_tool(tool)["function"]` 的基线快照（2026-11-11）；
   `to_lc_tools()` 返回原函数，所以 `bind_tools` 看到的 schema 与基线逐字节一致。
3. **循环依赖处理**：`calculator` / `deep_research` 定义在 `src/conversation_graph.py`，
   而后者 import 注册表。注册表**不在模块顶层**导入这两个函数，只在
   `to_lc_tools()` 里按 `_TOOL_MODULE_BY_NAME` 惰性 `importlib.import_module`；
   此时 `TOOLS` 赋值点位于两个函数定义之后，导入可正常解析。
   已单独验证“先 import registry 再调 to_lc_tools”的导入方向，5 个工具正常。
4. **既有导出保留**：`read_offload` / `search_knowledge` / `search_tavily` 三个顶层 import
   在 `TOOLS` 搬家后不再被使用，但为保持模块公开名字不变，保留并标
   `# noqa: F401 - 保持既有导出`（未改其他任何逻辑）。
5. **注册表只填值**：`register()` 除入表外只做两项防御——重名 `ValueError`、
   `spec.name` 与注册名不一致 `ValueError`；不做执行/预算/超时。

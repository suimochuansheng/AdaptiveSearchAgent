## 5. 降级文案

### 5.1 Server 断开后再调（A5，不抛栈）

```text
[PASS] A4 word_count("hello world") -> 字符数：11，词数：2，行数：1
[PASS] A5 降级文案：该 MCP 工具当前不可用（word_count）：MCP Server 未连接或已断开。可以改用内置工具，或稍后重试。
```

链路：`close_mcp_session()`（或 Server 异常退出）→ `_SESSION = None` /
调用失败被 catch → `mark_unavailable(name)` → 后续调用直接返回上面这句，
**不打网络、不抛异常、会话不崩**。`unit_convert` 同理。

### 5.2 Server 启动失败（A6 + 真启动）

命令改成 `false`：

```text
[PASS] A6 raised=None warnings=1 内置工具=['search_knowledge', 'search_tavily', 'calculator', 'deep_research', 'read_offload']

$ ENABLE_MCP=True MCP_SERVER_CMD=false poetry run uvicorn api_main:app --port 8097
HEALTH_OK after 4s
WARNING  MCP 工具加载失败，本次启动只提供内置工具：MCP Server 握手未完成：子进程未启动或提前退出（检查命令 / 参数 / 依赖）
（全日志 WARNING 计数 = 1；/health 200；5 个内置工具照常可用）
```

只 warning、不阻塞启动：`_register_mcp_tools()` 把整个加载包在 `try/except Exception` 里，
握手阶段的 SDK 取消已转成普通 `RuntimeError`；失败清理路径 `quiet=True`，不会多刷第二条 warning。

## 8. 已知未做（有意留白）

1. **只做 tools**：MCP 的 resources / prompts 未接（按卡范围）。
2. **不做审批**：`requires_approval=False` 是契约；审批是危险工具的语义。
3. **断线不自动重连**：`mark_unavailable()` 之后该工具一直返回降级文案，要恢复得重启进程
   （或再调一次 `load_mcp_tools()` + 重新注册）。本卡不引入后台重连。
4. **一个进程只连一个 MCP Server**：`_SESSION` 是模块级单例；多 Server 需要改成
   name → session 的映射，不在本卡范围。
5. **重名策略**：与内置工具重名时 `register()` 抛 `ValueError`，`_register_mcp_tools()` 跳过该工具并
   warning，不会让整批注册失败；不做自动改名。
6. **`python` 命令解析**：`MCP_SERVER_CMD` 传 `python` / `python3` 时替换成当前解释器
   （`sys.executable`），保证子进程用本仓库 venv 里的 mcp；子进程 cwd 固定为仓库根，
   所以 `MCP_SERVER_ARGS` 里的相对路径在任意 cwd 下都有效。这条已在代码注释里写明。
7. **关闭顺序**：`ClientSession` 退出会 cancel 自己的 task group 并抛 `CancelledError`，
   所以上下文按“进入顺序倒序、每个单独 try/except”释放，避免跳过 `stdio_client`
   导致子进程泄漏（这是本卡踩到的坑，已在 `mcp_client` 模块 docstring 记录）。

## 4. 追踪关联（第 4 条要求）—— 没有降级

子代理内部 span 落在**本轮同一个 `trace_id`** 下，且 `parent_span_id` **就是调用它的那条
`subagent_task` tool span**（没有被降级成独立 trace + `attrs.subagent_of`）。

做法：

1. tool span 由 `SpanCollectorHandler` 在 `on_tool_start` 创建，工具函数本身拿不到句柄；
   但工具执行时 `var_child_runnable_config` 里带着回调管理器，从 handler 的进行中 span 表
   按“名字 = `subagent_task` + 未结束”反查（`_active_tool_span()`）。
2. 进入子图前绑定一个**影子 turn 上下文**（`bind_turn`，`trace_id/session/turn_index` 全部复用
   tool span 的），并把 `ctx.root` 指向 tool span；
3. 子图**不显式传 callbacks**，靠 LangChain 回调继承（`_run_subagent` 里有注释：显式再传一份会
   重复产生 span，冒烟时抓到过 4 条 echo span，删掉显式回调后恢复 2 条）；
4. 退出时把子代理产生的 span 并回外层 turn 的 span 列表，保证本轮 `span_count` 汇总完整。

冒烟抓到的真实 span 树（同一 `trace_id=991e2a8a…`）：

```text
span turn  turn               id=11cd6234 parent=
  span llm FakeChatModel      id=f24b8098 parent=11cd6234   # 主 Agent 的模型调用
  span tool subagent_task     id=6ccc206e parent=11cd6234   # 调用子代理的那条 tool span
    span llm FakeChatModel    id=cb19b3e4 parent=6ccc206e   # 子代理第 1 步
    span tool echo_note       id=5d5d496c parent=6ccc206e
    span llm FakeChatModel    id=1c2b6760 parent=6ccc206e   # 子代理第 2 步
    span tool echo_note       id=32b76164 parent=6ccc206e
    span llm FakeChatModel    id=3668624e parent=6ccc206e   # 子代理最终结论
  span llm FakeChatModel      id=d3ebce6b parent=11cd6234   # 主 Agent 收摘要后的回答
```

## 5. 已知未做 / 已知边界（v1 明说）

1. **不做子代理专用工具集**（卡面明确不做）：子代理与主 Agent 共用同一套工具（含自己），
   深度上限 1 层靠递归守卫，不靠裁剪工具列表。
2. **不做子代理审批**：`requires_approval=False`、`permission="external"`（外部只读语义）。
3. **不把主会话历史传给子代理**：初始消息只有 `goal + constraints`；这是上下文隔离的硬边界。
4. 子代理的系统提示仍是主图的 `SYSTEM_PROMPT`；v1 不做子代理专用人设 / 专用模型。
5. 子代理每次新建 `MemorySaver`，**跑完即弃**：checkpoint 与主会话完全隔离（不存在“共享
   checkpointer 的隔离边界”问题），代价是子代理会话不可恢复、不支持 HITL 中断。
6. `SUBAGENT_MAX_TURNS` 用 LangGraph 的 `recursion_limit = 2*max_turns+1` 实现；超限时回传
   最后一个**有文本**的 AI 消息（没有就返回可读兜底文案），不会抛栈。
7. `_active_tool_span()` 反向依赖 `SpanCollectorHandler._spans`（回调内部结构）：
   同一 ToolNode 轮次里**并发**发起两个 `subagent_task` 时，按“最后一条未结束的 tool span”
   匹配，可能把两个子代理的 span 挂到同一条父节点下。v1 接受（单调用是常态；预算与递归
   守卫不依赖它）。彻底解法是让追踪层显式暴露当前 tool span，属后续卡。
8. 子图 `ainvoke` 的初始消息用 `HumanMessage` 包一层“子任务目标：…”，没有单独的子代理
   system prompt；模型若在子代理里再调 `subagent_task`，会先收到守卫文案再继续作答（冒烟已验证）。
9. 子代理超时后 `asyncio.wait_for` 取消整个子图任务；子图里正在跑的工具也会被取消
   （`MemorySaver` 丢弃，无残留）。主会话不受影响。

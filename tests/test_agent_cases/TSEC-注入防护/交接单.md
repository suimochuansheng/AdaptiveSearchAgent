## 1. 威胁模型

### 三类不可信来源（共用同一道收口）

| # | 来源 | 进入上下文的路径 | 本轮 |
|---|---|---|---|
| 1 | **工具输出** | `search_tavily` 抓回的网页、`search_knowledge` 的文档片段、`read_offload` 回读的原文、`deep_research` 的报告 | 已覆盖 |
| 2 | **技能正文** | `load_skill(name)` 读出的 `SKILL.md`（技能包可能是别人写的） | 已覆盖 |
| 3 | **用户输入** | 用户消息 / 前端输入 | **本轮不做**，只在 `docs/security.md` 记为已知未做 |

### 攻击形式

- **指令覆盖**：“忽略以上/之前的指令”“ignore previous instructions”“disregard the above”；
- **系统提示套取**：“输出你的系统提示”“system prompt”；
- **角色冒充**：“你现在是 …”；
- **边界逃逸**：内容里夹带 `</untrusted>` 或 `<untrusted source="system">`，试图提前闭合
  包裹、把后续内容伪装成可信区，或伪造新的来源。

### 防护原则

数据侧包裹（不是只在 prompt 里“求模型别听”）：固定边界 + 边界中和 + 命中时警示行；
**只标记、不删内容**——删内容会破坏正常文档，也会给模型错误的完整性预期。

## 2. 落点与实现

| 文件 | 改动 |
|---|---|
| `agent/adapters/tools/untrusted.py`（新增） | `wrap(content, source)`、`suspect(content)`、`neutralize(content)`、`WARNING_LINE`、`PROMPT_NOTICE`；零第三方依赖、不读配置 |
| `src/tools/offload.py` | `shrink_tool_message` 在**压缩 / 卸载之后**对最终 content 调 `wrap`；开关关闭时原路径原样返回（+10/-1 行，在 +12 行内） |
| `agent/adapters/tools/skills_tools.py` | `load_skill` 只返回原文；作为工具结果经 `shrink_tool_message` 统一包裹（`source="load_skill"`），调用点唯一 |
| `src/conversation_graph.py` | 构建 system prompt 时按开关追加 `PROMPT_NOTICE` 一行，不写死在 `SYSTEM_PROMPT` 模板里（+4） |
| `config.py` | 文件末尾“新功能开关”区追加 `ENABLE_TOOL_OUTPUT_GUARD: bool = False`（+5） |
| `docs/security.md`（新增） | 威胁模型 / 防护位置 / 已知局限 / 开关矩阵 / 复现 |
| `scripts/smoke_injection.py`（新增） | 4 个演示 + 开关关闭逐字节回归 + 系统提示开关检查 |

**为什么选 `shrink_tool_message` 一处收口**：`tools_node` 对每条 `ToolMessage` 都调用它，
因此一次覆盖 5 个内置工具 + MCP 工具 + 子代理工具；且它已经在做“进 prompt 前”的
压缩/卸载，把包裹放在最后一步，`[已卸载] … read_offload(pointer=…)` 指针文本也会落在
`<untrusted>` 内部，不会被模型误当可信指令。

**边界中和**：内容里任何 `<\s*/?\s*untrusted`（大小写、空白变体）都被拆成
`< /untrusted>` / `< untrusted`，无法闭合或伪造新边界；`source` 属性只保留
`[A-Za-z0-9_.:-]`，防属性注入。**调用点唯一**：`wrap` 不做“内容自称已包裹”的短路
（那会被 `<untrusted` 开头劫持），只允许 `shrink_tool_message` 调用；`load_skill`
只返回原文，作为工具结果必然经过该收口，因此只包一层。

## 6. 已知局限（与 docs/security.md §4 一致）

- **不能 100% 防住**：包裹与警示降低的是“模型把数据当指令”的概率，不是物理隔离；
  注入文本仍在上下文里，模型仍可能被更隐蔽的话术绕过。这是纵深防御的一层。
- **只标记、不删内容**：刻意不做内容清洗，避免破坏正常文档、避免给模型“内容已净化”
  的错误安全感。
- **边界中和是字面量级的**：覆盖 `<untrusted` 的大小写 / 空白变体，不处理 Unicode
  同形字、HTML 实体、Base64 等编码绕过。
- **讲防护的文章也会被改写**（OI-TSEC-003）：正文中形如 `<untrusted>` 的字样会被
  改写成不可闭合形式（`< /untrusted>`）；这是安全与保真的取舍，C2 探针即此已知取舍。
- **用户输入侧本轮未做**：用户消息不走 `wrap`；未来若做，应在消息进图之前单独收口，
  不能复用 `shrink_tool_message`（它只处理 ToolMessage）。
- **真正的兜底不靠本层**：输出侧校验 + 权限最小化 + 审批，这三条本项目已有
  （契约与工具白名单、`permission`/预算、HITL 审批）。

## 9. 缺陷 1/2 修复记录（OI-TSEC-001/002）

### 9.1 缺陷 1（严重）：内容自证已包裹 -> 防护整段失效

**现象**：`wrap` 开头 `if text.lstrip().startswith("<untrusted"): return text`。攻击者让
工具输出整体以 `<untrusted source="system">…</untrusted>` 开头，整段原样回灌，绕过包裹
（测试窗口 A3 的 4 个“开头即伪边界”变体全部失败）。

**修法**：
- 删除该短路，`wrap` 永远包裹并中和内层伪边界；
- 幂等改由**调用点唯一**保证：`shrink_tool_message` 是唯一 `wrap` 调用点；
  `load_skill` 不再自己 wrap，只返回原文，作为工具结果经过收口包一次；
- `wrap` docstring 明确写“本函数不做幂等判断；调用点必须唯一，否则会双层包裹”。

**取证**（A3 开头 4 变体全部通过）：

```text
[PASS] A3.开头1 开头即伪造 system 块 + 二次开块 — 边界=(1,1) 原样返回=False 无警示=False
[PASS] A3.开头2 开头即伪边界 + 前导空白 — 边界=(1,1) 原样返回=False 无警示=False
[PASS] A3.开头3 开头即伪开标签（无闭合） — 边界=(1,1) 原样返回=False 无警示=False
[PASS] A3.开头4 开头即闭合标签（提前截断） — 边界=(1,1) 原样返回=False 无警示=False
```

双块载荷实测（内容整体是两段 `<untrusted …>…</untrusted>`）：

开关打开但画像存在 -> 防护句丢失。

**修法**：先拼画像，**最后**追加 NOTICE（`src/conversation_graph.py`）。

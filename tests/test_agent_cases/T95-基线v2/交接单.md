## 4. 差异结论

- **与 §7（raw，9.65）**：A 9.70，差 **+0.05**（阈值 0.3 以内）→ 治理未降质；B +0.10、C +0.20
  同样在阈值内。A/B/C 的逐题差异只出现在 q005/q011/q013/q014/q018（同工具 `search_knowledge`、
  同答案路径，裁判给分 ±1），属 §4 记录的裁判波动。
  - A 组超出前先查了环境：同裁判、同题集 sha256、0 失败、0 SSE error、平均工具调用恒为 1.00，
    与 §7 的可比条件一致 → 结论是波动，**未改阈值、未改题、未换裁判**。
- **审批链路代价（C vs B）**：均分差 **+0.10**、平均耗时差 **+0.1s/题**（29.7s vs 29.6s），
  在裁判波动/进程噪声内。注意：**20 题没有一题调用 `deep_research`（唯一需审批工具）**，
  所以 C 组 `auto_approved=0`，审批分支实际未进入——这 0.10 分 / 0.1s 是"HITL 接线开销 + 裁判波动"，
  **不是审批执行成本**；审批执行成本本轮无法测出（没有触发审批的题）。
- **自动放行链路已单独验真**：C 组后端另发 1 次 `deep_research` 探针
  （`thread_id=g11-probe-hitl`，不计入 20 题）：日志出现
  `【评测专用】EVAL_AUTO_APPROVE=1，自动放行需审批工具 deep_research（累计 1 次；生产禁用）`，
  随后 `tool_call`/`token`/`final` 正常（未挂起等审批），最终回答带报告链接。
- 三组 20 题均 0 SSE `error`、0 失败题。

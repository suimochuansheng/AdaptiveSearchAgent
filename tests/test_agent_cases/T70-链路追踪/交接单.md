## 5. 设计要点与关键取舍

1. **端口最小**：`Tracer` 只有 `start_span(name, kind, *, parent=None, attrs=None)` 与
   `end_span(h, *, status="ok", attrs=None)`；`SpanHandle` 带
   `span_id / trace_id / start / turn_index / session_id`（另有父子关联与 attrs 等内部字段）。
2. **落盘口径**：`TRACE_DIR/<YYYY-MM-DD>.jsonl`；`open(path, "a")` + **一次** `write()`；
   路径在第一次真正写 span 时才 `mkdir`，所以 flag 关/无 span 时目录都不会出现。
3. **turn 上下文**：`turn_span` 用 `contextvar` 绑定 `trace_id / session_id / turn_index`，
   llm/tool span 自动挂到 turn 根下；拿不到上下文时优先复用“进程内唯一活跃轮次”，
   再拿不到就跳过该 span 并 warning 一次（不产生孤儿节点）。
4. **父子关系**：`turn` 的 `parent_span_id=null`；`llm`/`tool` 的父 id 恒为同一轮的 turn 根，
   符合契约 §5 的“tool 的父指向 turn”。
5. **一轮汇总**：turn 关闭时聚合子 span —— `tools`（工具名列表）、`tokens_in/out`（子 span 求和）、
   `cost`（G5 账本快照）、`span_count`（含 turn 自身）。
6. **错误口径**：契约十字段里没有 `status`，所以 **status 不进 JSONL**；错误通过
   `attrs.error_kind` 表达（`end_span(status="error")` 且未给 `error_kind` 时补 `fatal`）。
   `SpanHandle.status` 保留内存态，冒烟脚本用它断言 “tool span status=error”。
7. **LangChain 版本适配**：本仓库 `langchain-core 1.6.3` 的 chat model 完成事件实际派发到
   `on_llm_end`（没有 `on_chat_model_end` 派发）；因此同时实现 `on_llm_end` / `on_chat_model_end`，
   按 `run_id` 弹栈幂等，不会双写。`on_chain_start/end` 只做 no-op 透传。
8. **token 口径**：优先 `llm_output.token_usage`，其次 `AIMessage.usage_metadata`；
   取不到就**省略** `tokens_in/out`（不写 0 占位）。`cost` 不在回调里算。
9. **turn_index**：run 前 `await graph.aget_state(config)` 数历史 `HumanMessage` 条数 **+1**
   （契约要求从 1 开始；新会话空状态 -> 1）；`aget_state` 抛错/拿不到 values 时退回 **0** + warning。
10. **失败降级**：JSONL 写失败只 warning 一次并本进程降级 Noop；回调内所有入口兜异常，
    追踪永远不影响模型/工具/会话；Langfuse 缺 handler 时只挂 collector。

## 7. 已知未做 / 与冻结契约的差异（需计划窗口裁决）

1. **turn 汇总键超出 v1 白名单（重要）**：`docs/contracts/trace-span.md` §3 只允许
   `tool/tokens_in/tokens_out/cost/error_kind/approval_id`，但 T7-0 卡面要求 turn attrs 含
   `tools` / `span_count`。本实现按**卡面**写入这两个键（handler 产的 llm/tool span 仍严格
   只用白名单）；tracer 的 `_drop_illegal_attrs` 对 turn 放行这两个键、对其他 kind 直接丢弃。
   建议计划窗口开 `docs/revisions/YYYY-MM-DD-trace-span-v2.md`，在 §3 增加“turn 专用汇总键”
   或把它们改成从行数/名称推导，二选一后同步 `t12_checks.py`。
2. **`status` 不落盘**：十字段冻结，无 `status` 字段；错误只由 `attrs.error_kind` 表达。
   若验收要求 JSONL 里直接看到 `status=error`，同样需走 v2（新增字段会破坏十字段）。
3. **cost 为“会话累计”**：读 G5 `BudgetLedger.snapshot(scope)`，不是本轮增量；G5 关闭时为 0。
   这是卡面“读 G5 账本快照”的直接口径，T9-5 归因时请沿用。
4. **`turn_index` 的 +1**：卡面写“数 HumanMessage 条数”，契约要求从 1 开始，故正常路径 = 历史条数 + 1；
   只有 `aget_state` 失败时按卡面退回 0。
5. **未实现**：`event_tap`（契约 §7 列了 T7-0 消费方，但本卡落点未要求）、
   `compress/offload/approval` 三类 span、装饰器版（P1/T7-1）、审批 ID 关联。
6. **LangChain 事件名**：`on_chat_model_end` 在本版本不会被派发（完成走 `on_llm_end`）；
   两个都实现了，升级到会派发 `on_chat_model_end` 的版本也不会双写。
7. **上下文兜底**：跨任务丢失 contextvar 时，只在“进程内恰好一个活跃 turn”时兜底成功；
   多会话并发且框架丢上下文时，该 span 会被跳过（warning 一次），不会写孤儿行。

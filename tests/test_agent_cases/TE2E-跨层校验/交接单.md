## 5. SKIP 原因与已知未覆盖项

| 项 | 状态 | 原因 / 说明 |
|---|---|---|
| S3 的 **410 过期** | **SKIP** | 需要把 `APPROVAL_TTL_SECONDS` 调短并**重启服务**；本卡约束「不杀进程、不停容器」，故不测。S3 的 409 重放已覆盖「消费后凭据不可复用」 |
| S4 模型不调工具 | 设计为 SKIP | 模型依赖场景：本轮实测模型主动调了 `list_skills` + `load_skill`（PASS）；若未来模型不调，打印「模型未触发工具调用」并 SKIP，不误报 FAIL |
| **退出码 3** 分支 | 本轮未触发 | 全部 PASS 时为 0；仅当 S4 降级为 SKIP 才会出现 3（代码路径已实现，本轮未构造） |
| MCP 降级（工具不可用） | 本卡不做 | 卡面明确「MCP 降级场景本卡不做」 |
| 多 worker 指标聚合 | 未覆盖 | `prometheus_client` 默认 `REGISTRY` 在 `uvicorn --workers > 1` 下各进程独立；本卡只校验单进程（与 TMON 卡已知边界一致） |
| S5(b) 的父 span 可达性 | 有窗口边界 | 只校验「脚本启动后」的 span；脚本启动前开始、之后结束的 span 不在断言范围（本卡所有请求都在窗口内） |
| 真人并发流量 | 未覆盖 | 指标断言按 +1 精确判定；若脚本运行期间有人工请求打同一实例，S1(e)/S2(h) 可能因外部增量变红。设计上线程 id 带时间戳，DB/trace 不受影响 |
| 写数据库 | 未发生 | 脚本自身不写任何表；只有它触发的业务请求会写 `task_states` / `checkpoints`（与人工会话同一条路径） |
| 密码泄露面 | 已收敛 | Redis 密码只在子进程 argv 中（`--no-auth-warning`），不回显到 stdout/证据；`E2E_REDIS` 覆盖时由使用者自行保证 |

## 6. 脚本内部结构（对照卡面要求）

| 卡面要求 | 实现 |
|---|---|
| `probe()` | `probe()`：health + psql `SELECT 1` + redis `PING`，返回可读错误列表 |
| `snapshot_metrics()` | `snapshot_metrics()` -> `_parse_metrics()`：解析 requests / tool_decisions / approvals 三族计数 |
| `query_state(thread_id)` | `query_state()`：psql 查 `task_states`（`-tA` 裸输出；SQL 走 stdin + `-v :'tid'` 绑定） |
| `redis_scan(pattern)` / `redis_get(key)` | 同名函数，走 `docker exec redis-cli`（`--scan --pattern` / `GET`） |
| `latest_trace_spans(since_ts)` | 读 `logs/trace/<今天>.jsonl`，只取 `start >= since_ts`，坏行跳过 |
| 每个场景一个函数返回 `(结论, 证据串)` | `scenario_s1..s5`，结论 ∈ `{PASS, FAIL, SKIP}` |
| 汇总表格 + 末行统计 | `print_table()`（CJK 显示宽度对齐）+ `E2E: n passed, m failed, k skipped` + 复跑一句话 |

无新依赖：`httpx` 已是项目现有依赖（`httpx 0.28.1`），其余全部标准库。
`ruff check` / `ruff format --check` / `mypy` 均通过。

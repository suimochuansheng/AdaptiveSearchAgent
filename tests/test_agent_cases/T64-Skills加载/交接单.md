## 1. 设计取舍：为什么选渐进披露（B）

四层上下文预算里的 **stable（稳定区）** 是稀缺资源：系统提示、角色设定、工具说明都
在这里，每轮都随 prompt 发送。如果把每个技能的正文都拼进系统提示（方案 A），技能一多
就会挤占对话历史与工具结果的空间，而且大部分技能在单轮里根本用不到。

本卡采用 **方案 B（渐进披露）**：

1. 模型先调 `list_skills()` 看索引：每行只有 `name — when_to_use`，3 个技能约 100 token；
2. 需要时再调 `load_skill(name)` 读正文；正文上限 `SKILL_MAX_BODY_TOKENS=2000`；
3. **v1 完全不动图结构**，也不往系统提示注入索引——只加两个工具，靠模型自己
   “先 list 再 load”。这是本卡的设计取舍，不是缺陷。

代价：多一次工具往返；模型需要从两个工具的 docstring 知道调用顺序。收益：稳定区
不随技能数量线性膨胀，技能可以独立增删（热加载），不改图、不改 prompt 模板。

| `tests/test_agent_cases/README.md` | case_id 区间表新增 `T64-` 行 |

**安全边界**：`load(name)` 先用 `^[a-z0-9-]+$` 校验，再在 `scan()` 结果的 name 白名单里
查找，只读 `SkillSpec.path`；**没有任何“用 name 拼路径”的代码**。`scan()` 只接受
`SKILLS_DIR/*/SKILL.md`，不递归、不远程下载。

**热加载**：`_CACHE[path] = (st_mtime_ns, st_size, spec|None)`。文件新建 / 修改（mtime 或
size 变）/ 删除，下一次 `scan()` 自动重读或剔除；坏的 `SKILL.md` 缓存为 `None`，文件没变
就不重复 warning。3 个文件的扫描成本可忽略，不需要重启进程。

## 6. 热加载证据

`scripts/smoke_skills.py` 实际做的三步：

1. 新建 `skills/tmp-demo/SKILL.md`（`when_to_use: 冒烟热加载第一版`）→
   不重启，`list_skills()` 立刻出现 `tmp-demo — 冒烟热加载第一版`；
2. 改写同一文件为 `when_to_use: 冒烟热加载第二版`（size 变）→
   下一次 `list_skills()` 读到 `第二版`，不再出现 `第一版`；
3. `shutil.rmtree` 删除 → 下一次 `list_skills()` 不再出现 `tmp-demo`。

断言输出见 §5.2 的三条 `[PASS]`。删除在 `finally` 里执行，冒烟后 `skills/` 只剩 3 个正式技能。

## 7. 路径穿越防护

| 输入 | 结果 |
|---|---|
| `../etc/passwd` | `已拒绝：技能名不合法 …`，未读文件 |
| `../../etc/passwd` | 同上 |
| `/etc/passwd` | 同上 |

实现顺序：`^[a-z0-9-]+$` 校验 → `scan()` 的 name 白名单查找 → 只读 `SkillSpec.path`。
所以即使有人把 `SKILL.md` 的 frontmatter 写成 `name: ../../etc/passwd`，`scan()` 也会因
name 不合法跳过；`load()` 不会把它拼进路径。

## 8. 已知未做 / 边界（v1 明说）

1. **不往系统提示注入索引**：本卡选“模型自己 list + load”，图结构与 prompt 模板零改动；
   如果后续要做“索引自动进稳定区”，是另一张卡（会改图）。
2. **不做自动触发**：没有“按问题自动匹配技能”的规则/向量召回，由模型判断是否 list/load。
3. **不做远程加载 / 下载**：只读本地 `SKILLS_DIR`。
4. **不做技能版本 / 依赖管理**：同名重名跳过并 warning，不做优先级合并。
5. **mtime 缓存粒度**：以 `st_mtime_ns + st_size` 判断；若容器文件系统 mtime 不可靠，
   退路是每次 `scan()` 都重读（只有 3 个文件，成本可忽略），本机实测热加载正常。
6. **`SKILLS_INDEX_MAX`**：只限制返回条数，不做分页；技能很多时需要模型自己缩小范围或
   后续卡加分页。
7. **空 body**：frontmatter 合法但正文为空时按空正文返回，不视为损坏文件。

# TEG 评测门禁 交接单（补丁：阈值下限 + 逐题抖动证据）

- 卡号：**TEG「轻量评测门禁」**（开发窗口，判据数学修正）
- 日期：2026-11-24
- 基线 commit：`79b0df1`（测试窗口已合入有效性守卫复验）
- 结论：**已完成**。有效阈值不再直接取 0.0408，而是
  `max(记录方差, 单题当量)`；20 题时单题当量 = 0.05，修掉“净降 1 题必然 FAIL”的假阳性。
  同时增加逐题抖动（升/降/不变）与双侧符号检验，作为报告证据，不参与判定。

## 1. 背景：实测数据暴露的算术问题

同配置 A 跑两次：

- 均值差 **0.0000**；逐题 **2 升 / 2 降 / 16 不变**；
- 单题当量 = 1/20 = **0.05**；
- 旧阈值是记录方差 **0.0408 < 0.05**，于是“净降 1 题”（delta = -0.05）必然
  `FAIL_DEGRADED`。B/C 相对 A 的 -0.05 正是净 1 题，被旧判据误判。

## 2. 修 1：阈值下限取单题当量（核心）

`evals/gate.py`：

```text
score_step       默认 1.0；可从 per_case 分数差推最小正步长
n_cases          优先 meta.dataset_size（全量题数），缺省共同题数
one_case_weight  score_step / n_cases
effective_threshold = max(recorded_variance, one_case_weight)
```

- 三态判定全部改用 `effective_threshold`；
- `GateResult` 新增 `score_step / n_cases / recorded_variance / one_case_weight /
  threshold_used / delta_in_cases`；`threshold` 保留并等于 `threshold_used`（兼容）；
- reason 示例（20 题、净降 1 题）：

```text
PASS：delta=-0.0500（candidate-baseline；净值 1.0 题当量）；有效阈值 0.0500
（方差 0.0408 与单题当量 0.0500 取大），同口径无漂移；
逐题 1 升 / 2 降 / 17 不变，符号检验 p=1.00（不显著）
```

- 净降 1 题（-0.05）-> PASS；净降 3 题（-0.15）-> FAIL_DEGRADED；
- `--variance 0` 不再报错：方差 0 时有效阈值退化为单题当量（旧边界语义已更新）。

## 3. 修 2：逐题抖动证据（不进判定）

- `flips = {"up": n, "down": m, "unchanged": k}`；
- 双侧符号检验：`p = min(1, 2 * sum_{i<=min(up,down)} C(n,i) / 2^n)`，
  用 `math.comb` 实现，不引新依赖；
- `GateResult` 新增 `flips`、`sign_test_p`；
- reason 结尾追加：
  `逐题 2 升 / 2 降 / 16 不变，符号检验 p=1.00（不显著）`；
- 抖动只作证据，不改变三态结论。

## 4. 修 3：报告显式呈现

`evals/report.py` 在配置矩阵表下方加两行（有对比结果时）：

```text
单题当量：0.0500 ｜ 有效阈值：0.0500（方差 0.0408 与当量取大）
逐题抖动：升 2 / 降 2 / 不变 16 ｜ 符号检验 p=1.00（>0.05，不显著）
```

结论段仍原样引用 `GateResult.reason`；无对比基线时两行显示“—（无对比基线）”。

## 5. 修 4：`--variance auto`

```bash
python -m evals.gate --baseline X --candidate Y --variance auto
```

- 在 `evals/results/` 中找**同 config、同 git_commit、同 dataset_sha256、valid 且非 partial**
  的 run，取最近两次，用 `abs(mean2 - mean1)` 当记录方差；
- 打印 `variance auto: 0.0000（runA vs runB）`；
- 找不到时回退 `0.0408`，并打印
  `未找到可用的重复 run，回退到 0.0408`；
- 数字/auto 之外的输入给可读错误（退出码 2）。

## 6. 冒烟（18 条 = 原 15 + 新 3）

新增：

1. **净降 1 题**（20 题、delta=-0.05）-> 阈值 0.05 -> `PASS`；
2. **净降 3 题**（delta=-0.15）-> `FAIL_DEGRADED`；
3. **2 升 2 降**（delta=0）-> `PASS`，reason 含“符号检验”，报告含两行证据。

旧 15 条中“方差为 0 -> 可读错误”随新公式改为“方差 0 -> 有效阈值取单题当量”；
断言总数仍 18。

## 9. 已知边界

- `score_step` 是从“共同题分数差”推最小正步长；整数 1~10 分时稳定为 1.0，
  分数带小数时可能把一次 0.5 的变化推成 0.5，需要时可显式传 `score_step`（compare API）。
- `n_cases` 优先 `meta.dataset_size`；旧 run 缺该字段时退回共同题数。
- 单题当量只解决“净 N 题”的算术下限，不解决裁判噪声；2 升 2 降仍要靠符号检验/人工看。
- 符号检验只看升/降次数，不看幅度；p 大只说明“方向不显著”，不能证明没有退化。
- `--variance auto` 要求同 config/同 commit/同数据集且非 partial；找不到就回退 0.0408。
- `--variance 0` 现在合法（有效阈值退化为单题当量），旧“方差 0 报错”边界已失效。
- 未 push；未写台账；未删除任何 run 目录；未改 `teg_checks.py`。

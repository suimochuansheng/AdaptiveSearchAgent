## 2. gate 行为细节

- `GateResult` 新增：`quality_warning`、`compared_cases`、`skipped`、
  `missing_in_candidate`、`missing_in_baseline`、`partial_compare`、
  `code_version_changed`、`baseline_git`、`candidate_git`；
  保留 `common_cases`（= compared_cases）、`passed`、`verdict` 兼容。
- 判据仍是三态：
  - `delta < -variance` -> `FAIL_DEGRADED`；
  - `delta > +variance` -> `WARN_IMPROVED`；
  - 其余 -> `PASS`。
- CLI 新增：`--allow-invalid-baseline`、`--allow-invalid-candidate`、`--allow-partial`；
  默认无效/题集不一致 -> 退出码 2；PASS/WARN -> 0，FAIL -> 1。
- `--json` 输出同步包含 `status/compared_cases/skipped/quality_warning/code_version_changed` 等字段。

## 3. run.py / store.py / report.py

- run.py：
  - `_previous_run(..., include_invalid=False)` 默认过滤 `valid_for_quality=false`；
    `--allow-invalid` 才纳入，并把 allow 标记传给 gate；
  - `--limit` 小于数据集题数时 meta 写 `partial=true / publishable=false`；
    全量写 `false / true`；
  - 报告仍由 `report.write_markdown` 统一生成。
- store.py：
  - `META_REQUIRED` 增加 `partial`、`publishable`，并校验 bool；
  - 额外校验 `partial=true` 时 `publishable` 不能为 true。
- report.py 顶部按情况输出警告（可叠加）：
  - 无效 run；
  - 非全量 run；
  - `quality_warning`（放行的无效 run）；
  - 两次 run 代码版本不同；
  - 仅比较共同题（`compared_cases` / `skipped`）。
  元信息表新增「全量性」「可发布」两行；旧 run 缺字段显示“未记录（历史 run）”。

## 4. 冒烟新增断言（共 15 条）

`scripts/smoke_eval_gate.py` 在原 10 条基础上补 5 条：

1. 无效基线 -> 默认 exit 2；`--allow-invalid-baseline` -> 继续且 `quality_warning` 非空；
2. 题集不一致 -> 默认 exit 2 且列出 `q003`；`--allow-partial` -> `compared_cases=2 / skipped=1`；
3. 零差值 -> reason 含“无差异”；
4. 非全量 run -> `meta.partial=true / publishable=false`，report 含“不可用于发布”；
5. 两 run git 不同 -> `code_version_changed=true`，report 含“代码版本不同 / 不能归因于配置开关”。

## 7. 已知边界

- 有效性判定只看显式 `valid_for_quality is False`；**缺少该字段的历史 run 视为有效**
  （向后兼容），但历史链路验证 run 已标注 false。
- 题集不一致按 **case_id 集合**判断；同一题号但分数缺失属于“有效题不足”，走共同题 < 2 的报错。
- `--allow-partial` 只比共同题，结论不可跨版本比较；报告会明确写 `compared_cases / skipped`。
- 代码版本只比对 `meta.git_commit` 短哈希；**同 commit 但工作区 dirty 的改动不会触发**
  `code_version_changed`。发版前应保证评测时工作区干净。
- 非全量 run 即使环境全绿，也 `publishable=false`，不能用于发布/写简历。
- 旧 run 的 `report.md` 是历史生成物，未重新生成；以 meta 与新建报告为准。
- 冒烟里的探活失败用例把模型/PG/Redis 探活打桩，只真实探测 RAG 死端口，不依赖外部服务。
- 未 push；未写台账；未删除任何 run 目录。

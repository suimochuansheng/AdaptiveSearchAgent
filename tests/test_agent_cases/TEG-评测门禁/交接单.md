## 1. 五条 OI 修复

| OI | 修复 |
|---|---|
| **007** PASS 不得写“失败归因” | gate：`FAIL_DEGRADED` 写「失败归因：…」，`PASS` / `WARN_IMPROVED` 写「变化归因：…」；report 第 3/5 节表头与标题同步切换（`失败归因` / `变化归因`） |
| **008** 措辞随 delta 变化 | `delta==0` -> “无差异（两均值完全相同）”；`0<|delta|<=阈值` -> “差异在单题当量内（{delta_in_cases:.1f} 题），不显著”；超出阈值正 -> “提升超出阈值，需人工复核”；负 -> “退化超出阈值” |

| **010** 数据集不一致 | 两 run `dataset_sha256` 不同默认退出 2，提示“两次 run 数据集不同（a… vs b…），不可直接比较”；`--allow-mixed-dataset` 才继续，`dataset_mismatch=true`，报告单独一行；与 `--allow-partial` 独立，可同时出现 |

## 2. 报告呈现

- diff 表头：PASS/WARN 为「变化归因」，FAIL 为「失败归因」；
- 第 5 节标题：
  - PASS/WARN：`## 5. 变化归因 case 清单（退化 / 报错 / 超时）`
  - FAIL：`## 5. 失败归因 case 清单（退化 / 报错 / 超时）`
- 顶部警告按情况叠加：无效 run、非全量、quality_warning、代码版本不同、
  仅共同题、数据集不同、样本过小，各占一行；
- 配置矩阵表下仍保留：
  `单题当量：0.0500 ｜ 有效阈值：0.0500（方差 0.0408 与当量取大）`
  `逐题抖动：升 1 / 降 2 / 不变 17 ｜ 符号检验 p=1.00（>0.05，不显著）`
- 结论段原样引用 gate 的 `reason`。

## 3. 冒烟（22 条 = 原 18 + 新 4）

新增：

1. PASS 时 reason/报告含“变化归因”、不含“失败归因”；
2. delta 非零且小于阈值 -> reason 含“差异在单题当量内”；
3. `n=2` -> `sample_warning` 非空，reason 与报告含“样本过小”；
4. 数据集不同 -> 默认 exit 2；`--allow-mixed-dataset` -> 继续且 `dataset_mismatch=true`。

## 6. 已知边界

- `sample_warning` 只提示、**不阻断**；`n_cases < 5` 的 PASS/FAIL 仍按三态给出，但判别力弱。
- “变化归因”只改措辞，不改变 `GateResult.failures` 字段（内部仍叫 failures）；
  报告通过 status 动态展示为“变化/失败”，下游读字段不受影响。
- 数据集不一致只在两侧 `dataset_sha256` 都非空且不同的时候触发；缺失 sha 的旧 run 无法判断。
- `--allow-mixed-dataset` 与 `--allow-partial` 独立，可同时出现，报告会各占一行。
- `delta_in_cases` 用单题当量归一化；当 `score_step` 推得很小（如 0.1）时，
  `delta_in_cases` 会很大，措辞里会显示对应题数。
- 代码版本差异的“含代码版本差异，无法归因”仍优先于普通超阈值措辞（沿用上一补丁）。
- 未 push；未写台账；未删除 run 目录。

## 1. 设计决策（延续上一轮，按补丁修正）

1. **不起新服务、不加前端、不新增依赖**：仍是 CLI + markdown 报告；评测执行器起的后端是
   已有 `api_main:app` 子进程，跑完即停。
2. **门禁逻辑与真实评测解耦**：`evals/gate.py` 的 `compare()` 仍是纯函数（零 IO、零模型调用）；

3. **判据改三态，替代双侧 abs()**：

4. **新结果只写 `evals/results/`**：`docs/baseline.md` 数字、`config.py` 默认值、`ci.yml` 均未改；
   `evals/results/` 仍 gitignore。

## 5. 补丁 4：冒烟断言

`scripts/smoke_eval_gate.py` 从 6 条扩到 10 条：

- 降质 -1.5 -> `FAIL_DEGRADED`（含工具未调用 / 超时归因）；
- 持平 -> `PASS`；+0.03（方差内）-> `PASS`；

- **RAG 指向不存在端口 -> `evals.run` 退出码 2，提示“环境未就绪：rag”**；

## 8. 已知边界

- **`WARN_IMPROVED` 退出码 0 不代表可直接发版**：只是“没退化”，报告会要求人工复核；
  发版清单应把 WARN 当“需说明”而不是“自动通过”。
- **探活只证明“能开跑”**：RAG 只查 `/health`，模型只出 1 token，PG/Redis 只测 TCP；
  不证明检索质量、PG schema、Redis 数据都正确。
- **`0.0408` 仍来自 Ragas 的 0~1 指标**，迁到 1~10 分 judge 上很紧；超阈值先查环境/裁判。
- **旧 run 没有 environment 字段**：只追加了 `valid_for_quality/note`，报告里环境行显示
  “未记录（历史 run）”；旧 `report.md` 是补丁前生成的，可能没有顶部警告，以 meta 为准。
- **单裁判、20 题样本小**；单题 ±1 分即可让 20 题均值动 0.05。
- **`--allow-degraded` 只用于链路验证**：meta 会永久标 false，不能拿来当质量基线。
- `tokens` 在 `/chat/conversation` 没有 kpi 帧时为 `null`，报告不据此判定。
- 未 push；未写台账行；未删除任何 run 目录。

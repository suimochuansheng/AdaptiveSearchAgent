# 开发行为规范（优先级高于一切）

## 🔴 最高优先级：沟通语言规范
- **强制使用简体中文**：无论用户使用何种语言提问，你必须使用简体中文进行思考、解释和回复。
- **代码注释与文档**：所有代码注释、文档字符串（docstrings）必须使用简体中文。
- **术语例外**：常见技术术语（API, SDK, JSON）可保留英文，但整体语境必须为中文。

## 工作流程
1. **需求理解**：分析请求，确认关联需求或问题。
2. **技术设计**：复杂功能先输出技术方案，确认后再编码。
3. **编码实现**：
   - 遵循下方 Python 编码规范。
   - 必要时补充单元测试。
   - 确保 import 顺序和格式正确。
4. **自动化验证**（编码后执行）：
   - `ruff check --fix .`
   - `ruff format .`
   - `mypy .`
   - `pytest`
5. **提交代码**：遵循下方 Git 提交规范。

## Python 编码规范
- 行长度 ≤ 100 字符。
- 导入顺序：标准库 → 第三方库 → 本地模块，组间空一行。
- 字符串优先使用双引号。
- 文档字符串使用三重双引号 `"""`。
- 所有函数参数和返回值必须有类型注解。
- 错误处理推荐 EAFP（如 `try/except KeyError`），避免过度检查 `if 'key' in dict`。
- 禁止使用 `eval()`、`exec()` 或动态构造 SQL。
- API Key、URL 等配置必须从 `config.py` 导入，禁止硬编码。

## Git 提交规范
- 格式：`<类型>(<作用域>): <描述>`
- 类型：`feat`(新功能)、`fix`(修复)、`docs`(文档)、`style`(格式)、`refactor`(重构)、`test`(测试)、`chore`(杂项)
- 示例：`feat(planner): 添加搜索计划生成节点`

项目技术背景（架构/环境/依赖）请参考 `CLAUDE.md`。
